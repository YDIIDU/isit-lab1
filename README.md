# Лабораторная работа №1
# Задание
Вариант 16. Система управления заявками на ремонт

Система предназначена для обработки заявок на ремонт помещений или оборудования. Пользователь должен иметь возможность сообщить о неисправности и указать ее описание. Сотрудники технической службы должны получать заявки, назначать ответственных и изменять статус выполнения.

## 1. Проблема и цель системы

### Проблема
В настоящее время заявки на ремонт помещений и оборудования принимаются по телефону, электронной почте или устным обращениям, что приводит к:
- Потере или забыванию заявок
- Отсутствию единого учета обращений
- Невозможности отследить статус выполнения
- Задержкам в назначении ответственных
- Неконтролируемому времени выполнения работ

### Цель
Разработать информационную систему для централизованного приема, учета и контроля выполнения заявок на ремонт помещений и оборудования, обеспечивающую прозрачность процесса для всех участников.

### Область применения
Система предназначена для использования в организациях любого размера, имеющих техническую службу или службу эксплуатации, для автоматизации процессов приема и обработки заявок на ремонт.

## 2. Анализ предметной области

### 2.1. Объекты предметной области

| № | Объект | Назначение | Основные характеристики |
|---|--------|------------|------------------------|
| 1 | **Пользователь** | Лицо, создающее заявку на ремонт | ID, ФИО, Email, Телефон, Отдел, Должность |
| 2 | **Заявка** | Обращение о неисправности | Номер, Тема, Описание, Дата создания, Адрес, Приоритет, Статус |
| 3 | **Сотрудник** | Исполнитель, назначенный на заявку | ID, ФИО, Должность, Специализация, Статус доступности |
| 4 | **Оборудование** | Объект, требующий ремонта | Инвентарный номер, Название, Модель, Дата установки, Местоположение |
| 5 | **Помещение** | Место, где требуется ремонт | Номер, Этаж, Корпус, Назначение, Состояние |
| 6 | **Статус заявки** | Этап обработки заявки | ID, Название статуса, Описание (Новая, В работе, Завершена, Отклонена) |
| 7 | **Комментарий** | Дополнительная информация по заявке | ID, Текст, Дата, Автор, Заявка |

### 2.2. Связи между объектами

1. **Пользователь создает Заявку**
   - Один пользователь может создать множество заявок
   - Каждая заявка принадлежит одному пользователю

2. **Заявка назначается Сотруднику**
   - Одна заявка назначается одному сотруднику
   - Один сотрудник может выполнять множество заявок

3. **Заявка относится к Оборудованию или Помещению**
   - Заявка может быть связана с одним оборудованием ИЛИ с одним помещением

4. **Заявка имеет Статус**
   - Каждая заявка имеет один текущий статус
   - Один статус может быть у множества заявок

5. **Заявка содержит Комментарии**
   - Одна заявка может содержать множество комментариев
   - Каждый комментарий относится к одной заявке

6. **Пользователь и Сотрудник пишут Комментарии**
   - Пользователь может добавлять комментарии к своей заявке
   - Сотрудник может добавлять комментарии к заявке

## 4. Пользователи и роли

| Роль | Назначение | Основные действия |
|------|------------|-------------------|
| **Пользователь** | Сотрудник организации, который сообщает о неисправности | - Создавать новую заявку<br>- Просматривать статус своих заявок<br>- Добавлять комментарии к заявке<br>- Прикреплять фото или документы к заявке |
| **Сотрудник техподдержки** | Специалист, обрабатывающий заявки | - Получать и просматривать все заявки<br>- Назначать ответственных исполнителей<br>- Изменять статус заявки<br>- Добавлять комментарии и решения<br>- Отклонять необоснованные заявки |
| **Администратор** | Управляющий системой | - Управлять пользователями (добавление, редактирование, удаление)<br>- Настраивать список статусов заявок<br>- Формировать отчеты по работе системы<br>- Управлять списком оборудования и помещений<br>- Просматривать статистику работы службы |

## 5. Функциональные требования

### Для роли «Пользователь»
- **FR-01.** Система должна позволять пользователю создавать новую заявку на ремонт.
- **FR-02.** Система должна позволять пользователю прикреплять файлы к заявке.
- **FR-03.** Система должна позволять пользователю просматривать статус своих заявок.
- **FR-05.** Система должна позволять пользователю добавлять комментарии к заявке.

### Для роли «Сотрудник техподдержки»
- **FR-06.** Система должна предоставлять сотруднику возможность просматривать все заявки.
- **FR-07.** Система должна позволять сотруднику назначать ответственного исполнителя.
- **FR-08.** Система должна позволять сотруднику изменять статус заявки.

### Для роли «Администратор»
- **FR-10.** Система должна предоставлять администратору возможность управления пользователями.
- **FR-11.** Система должна позволять администратору формировать отчеты.

### Общие требования
- **FR-04.** Система должна автоматически присваивать уникальный номер каждой заявке.
- **FR-09.** Система должна автоматически уведомлять пользователя об изменении статуса.
- **FR-12.** Система должна обеспечивать хранение всей информации в базе данных.
- **FR-13.** Система должна поддерживать поиск заявок по различным параметрам.

## 6. Концепция информационной системы

### Назначение системы

Система управления заявками на ремонт предназначена для автоматизации процесса приема, учета и контроля выполнения заявок на ремонт помещений и оборудования в организации. Система обеспечивает централизованную регистрацию обращений, назначение ответственных исполнителей и отслеживание статуса выполнения работ.

### Основные возможности

Система решает следующие задачи:

- Регистрация заявок на ремонт от пользователей
- Прикрепление файлов (фото, документы) к заявкам
- Назначение ответственных исполнителей на заявки
- Изменение статуса выполнения заявок
- Добавление комментариев к заявкам
- Просмотр истории и статуса заявок
- Уведомление пользователей об изменении статуса
- Формирование отчетов по выполненным работам
- Управление пользователями системы
- Управление списком оборудования и помещений

### Тип системы

Веб-приложение с клиент-серверной архитектурой.

### Основные компоненты

1. **Пользователь** — сотрудник организации, который взаимодействует с системой через браузер.

2. **Web-интерфейс** — набор веб-страниц для работы с системой:
   - Форма создания заявки
   - Личный кабинет пользователя
   - Панель сотрудника техподдержки
   - Административная панель

3. **Серверная часть** — обработка запросов и бизнес-логика:
   - API для работы с заявками
   - Аутентификация и авторизация пользователей
   - Логика назначения и обработки заявок
   - Генерация отчетов
   - Отправка уведомлений

4. **База данных** — хранение информации:
   - Пользователи
   - Заявки
   - Сотрудники
   - Оборудование
   - Помещения
   - Статусы заявок
   - Комментарии

### Результат использования

В результате работы системы пользователи получают:

- Удобный инструмент для быстрой подачи заявок на ремонт

- Своевременные уведомления об изменениях
- Возможность прикреплять фото и документы для точного описания проблемы

Сотрудники технической службы получают:

- Централизованную систему для эффективного распределения задач
- Инструмент для контроля выполнения заявок
- Возможность назначать ответственных и отслеживать сроки

Руководство получает:

- Отчетность и статистику работы службы
- Данные для анализа эффективности работы технической поддержки
